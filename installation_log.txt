GPU Drivers Stack
Kernel Level
	The kernel drivers for both intel and amd gpus are installed by default but amd gpu is using the older radeon driver instead of amd gpu. For my current laptop, Dell Inspiron 15-3567, it is not worth switching to the modern amdgpu driver. It introduces a lot unstability. The system hangs on shutdown, restart, logff and suspend. Also, even steam hangs when DRI_PRIME=1. PC building simulator game doesn't even launch either with DRI_PRIME=1 with or without enabling amdgpu. However, it can be enabled sometime in the future, if I end up with a system having a modern AMD GPU by following these instructions. It is changed by setting the kernel parameter in grub and also by creating a modprobe config amdgpu.conf in /etc/modprobe.d
	# /etc/modprobe.d/amdgpu.conf
	options amdgpu si_support=1
	options radeon si_support=0
	blacklist radeon
	For the grub config change this line:
	GRUB_CMDLINE_LINUX_DEFAULT="quiet splash radeon.si_support=0 amdgpu.si_support=1 resume=UUID=ff87c016-14ea-413a-8935-2e9330962c9d"
Opengl Level
	All the opengltools (mesa-utils which provides glxinfo) and drivers for both intel and amd gpu (mesa intel and radeonsi) are installed by default in ubuntu. Note that trying to drive DGPU with amdgpu driver somehow breaks opengl on this gpu.
Vulkan Level

	Amd gpu open cl has two optins. Clover which is old and buggy and currently not working on ubuntu 24 due to some library header file conflict. But rusticl which is the latest is working and its support will only increase further in the future. Ran the following command to remove clover
	sudo mv /etc/OpenCL/vendors/mesa.icd /etc/OpenCL/vendors/mesa.icd.disabled
	However rusticl doesn't select the correct driver unless it is explicitly told to do so with an export variable as follows

	On the intel opencl side, there are no issues and it works with neo properly.

07/04/2026 (Swati's birthday) Steam 
  Installed through the official deb file from the website. Also adds its own repo to apt.
  While the deb file is being installed, it tries to add around 11 more packages and 10 of them were already installed in my case and hence some of them (usually the 32 bit versions of the libraries/packages) were marked as manually installed. If you uninstalld steam in the future, you may want to mark them as manually installed so that you can remove them with sudo apt purge --autoremove. Those few packages which were mentioned as already installed but not marked as manually installed were probably already set to manually installed. If you want to aggressively, clean up your system, you may want to set them to automatically installed as well in the future when you uninstall steam. Anyway, most of these packages may not be removed with sudo apt purge --autoremove even after being set to automatically installed as they have many reverse dependencies. The entire list of changes can be seen in the file steam_changed_packages.txt

  When it comes to launching steam from either the desktop icon or from the gnome-search (searching by typing the super key), the desktop file, ~/Desktop/steam.desktop works just fine with the Exec line Exec=/usr/bin/steam %U. But the gnome search launching doesn't work fine, at least for my current Dell-Inspiron-15-3567 laptop. Because it tries to access my DGPU which is buggy with steam and hence it needs to be explicitly be forced to use my IGPU with by editing the file /home/keerthi/.local/share/applications/steam.desktop and changing line 37 from PrefersNonDefaultGPU=true to PrefersNonDefaultGPU=false to force the use of IGPU instead of DGPU. Note that changing the same line in the equivalent .desktop file for the desktop shortcut, ~/Desktop/steam.desktop has not effect as it seems to somehow always pick the IGPU by default due to the desktop environment. Alternatively the same can by achieved by changing the Exec line, line 30, to Exec=env DRI_PRIME=0 /usr/bin/steam %U in the same file. In future no such changes maybe required if you use a modern pc with relatively newer AMD gpu that supports the latest GPU kernel driver, AMD driver amdgpu instead of the older radeon.

  As for launching the actual game (PC Building Simulator is the only game that I play on steam at this time), the following launch command is used: gamemoderun vblank_mode=0 %command%   The vblank_mode=0 is for hard disabling vsync at the kernel level to improve input lag (which is not critical for the game that I play anyway). The gamemoderun is to put the cpu in performance mode for the gameplay. Note that if you are debugging when the game doesn't launch and wants to make sure that vulkan on any particular gpu is not the issue, add the variable PROTON_USE_WINE3D=1 to convert the vulkan calls to opengl so that game will at least run with opengl if vulkan is the only issue. This helps in isolating and confirming the issue when the game doesn't launch. Also, please note that on the current PC, Dell-Inspiron-15-3567, the game takes a lot of time to launch so please give it some time to launch before coming to the conclusion that the game is not launching. If you want to confirm that the game is indeed doing something in the background and not silently failing, launch it from the terminal once and you can confirm that steam is doing something by viewing the continuously changing stdout to the terminal.

    npm and nodejs are required for the python lsp server pyright and also by ai.copilot. nmp is required for installing some plugins such as these two through mason and nodejs is required for actually running the server. While installing npm through apt is sufficient for the pyright plugin, it is not sufficient for ai.copilot as it requires npm version 9 or above and the npm version in apt is 8. So I have installed npm and nodejs through nvm (node version manager) which is a tool to manage multiple versions of nodejs and npm on the same system. The installation instructions are followed from the official nvm repo (https://github.com/nvm-sh/nvm). You just need download the install script from that repo and run it. The script will download the binary to ~/.nvm and edit your .zshrc or .bashrc to add the binary and autocompletion options to the shell. After that the latest lts version of nodejs and npm can be installed with the following command:
    nvm install --lts
